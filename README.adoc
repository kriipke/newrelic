= NRQL Dashboard Generator
:toc:
:toclevels: 2

A dashboards-as-code compiler for New Relic. Define observability dashboards in concise YAML, compile them to New Relic's API-ready JSON, and manage them through the same Git workflows you already use for infrastructure.

== Dashboards-as-Code

Observability dashboards are infrastructure. They 

. encode institutional knowledge about what to watch, how systems fail, and what thresholds matter. Leaving that knowledge locked inside the New Relic UI means no version history, no peer review, no reproducibility, and no way to guarantee consistency across teams or accounts.
. ensure consistent deployment of the dashboards themselves across environments - the dashboards tend to be large complex JSON objects that themselves can contain sets of very complex queries. For that reason any deviationn in the JSON from one environment to the next could result in comparing dating in an erroneous manner leading to the next point.
. this dashboard-as-code generator ensures, for example, a dashboard showing the latency of service A in dev can meaningfully be compared to the latency of service A in the QA environment because the dashboards were generated in an identical manner.

This tool treats dashboards the same way Terraform treats cloud resources: source-controlled, reviewable, and repeatable.

== Features & Benefits

Below are the 

=== Version-controlled dashboards

Every dashboard definition lives in a YAML file in Git. Changes produce diffs. Diffs produce pull requests. Pull requests produce review. You get a full history of who changed what query, when, and why — without relying on New Relic's own audit trail (which only shows the final JSON blob, not the intent).

=== Cross-account consistency

Organizations running multiple New Relic accounts — separate environments, separate business units, separate regions — typically rebuild dashboards by hand in each one. This tool accepts a `--account` flag at compile time, so the same YAML config generates correct JSON for any account. One source of truth, many deployments.

=== Drift prevention

When someone edits a dashboard directly in the New Relic UI, that change lives outside version control and silently diverges from the YAML. Because the generated JSON is a deterministic compilation of the YAML, you can diff the API's current state against the repo's expected output to detect and revert manual overrides.

=== Faster onboarding

New team members don't need to learn the New Relic dashboard builder. They read the YAML, understand the NRQL queries, and submit a PR. The widget layout, visualization types, and NRQL syntax are all visible in one file — no clicking through a multi-step UI to understand what a dashboard actually shows.

=== Repeatable disaster recovery

If a dashboard is accidentally deleted or an account is migrated, recreating it means running one command against the YAML that was already in Git. No reconstruction from screenshots or memory.

=== Single compilation source for multiple outputs

The YAML is the canonical definition. From it, this tool generates the JSON that New Relic's API accepts. That same YAML can drive documentation generation, validation linting, and HTML mockup previews — all from one source of truth.

== How it works

.The compilation pipeline
image::pipeline.svg[Pipeline,align=center]

1. Write widget definitions in `config.yaml` using a slim schema — title, visualization type, layout position, and NRQL query.
2. Run the compiler with a target account ID.
3. Out comes `generated_dashboard_v2.json` — the full JSON payload the New Relic Dashboards API expects, with all wrapper fields, default blocks, and configuration wiring filled in.

The YAML is roughly 5x more concise than the output JSON. Constants like `linkedEntityGuids`, `platformOptions`, and `accountIds` are generated automatically — you only specify what actually varies per widget.

== Quick start

=== Prerequisites

- Go 1.23+
- A New Relic account ID

=== Build

[source,bash]
----
go build -o dashboard-gen main.go
----

=== Generate

[source,bash]
----
./dashboard-gen --account <YOUR_ACCOUNT_ID>
----

This reads `config.yaml` and writes `generated_dashboard_v2.json`.

=== Deploy to New Relic

[source,bash]
----
curl -X POST https://api.newrelic.com/v2/dashboards.json \
  -H "X-Api-Key: $NEW_RELIC_API_KEY" \
  -H "Content-Type: application/json" \
  -d @generated_dashboard_v2.json
----

== YAML reference

=== Widget definition

[source,yaml]
----
widgets:
  - title: "SLO Compliance (All Apps)"
    visual:
      type: billboard        # Visualization type: billboard, line, area, pie, table, stacked-bar
      legend: false          # true adds legend + facet "show other series" blocks automatically
    location:
      col: 1                 # Column position (1-based)
      row: 1                 # Row position (1-based)
    dimensions:
      width: 2               # Widget width in grid units
      height: 2              # Widget height in grid units
    query: |-
      SELECT clamp_max(sum(newrelic.sli.good) / sum(newrelic.sli.valid) * 100, 100) AS 'SLO (%)'
      FROM Metric
      FACET appName
      SINCE 1 hour ago
----

=== Visualization types

|===
| Type | Use case

| `billboard` | Single metric, big number display
| `line` | Metric over time
| `area` | Volume over time with fill
| `pie` | Categorical breakdown
| `table` | Faceted data in rows
| `stacked-bar` | Stacked volume over time
|===

=== Legend coupling

Setting `legend: true` automatically injects both the `legend` and `facet` configuration blocks into the output JSON, since faceted charts almost always need both. One boolean covers the common case without exposing the underlying API coupling.

=== Dashboard variables

The compiler injects three dashboard variables automatically:

|===
| Variable | Type | Purpose

| `appName` | NRQL | Dynamic dropdown populated from recent traffic
| `namespace` | STRING | Kubernetes namespace filter
| `clusterName` | STRING | Kubernetes cluster filter
|===

Update the default values for `namespace` and `clusterName` in `main.go` to match your environment before building.
